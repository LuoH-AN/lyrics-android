# 歌词搜索说明

本文说明当前源码的实际行为。极简小窗改动没有重写自动搜索、候选评分或缓存策略。

## 1. 歌曲信息来自哪里

读取音乐播放器公开的 Android MediaSession，获取歌名、歌手、专辑和时长。不是录音识曲，也不是从声音里提取歌词。

## 2. 先查本地，但主页和小窗的缓存行为不同

- **自定义 LRC**：按歌名、歌手匹配，优先使用；命中后不再联网搜索歌词。
- **主页**：自定义歌词 → 14 天内的主页缓存 → 联网。有效缓存命中后不会继续查询。
- **小窗**：自定义歌词 → 先显示 14 天内的小窗缓存 → 再联网更新。更新失败时保留已有缓存。

主页缓存保存在 SharedPreferences，小窗缓存保存在 WebView localStorage；二者目前不是同一份缓存。

## 3. 网络搜索不是挨个平台取第一条

通常同时查询 **LRCLIB、QQ 音乐和网易云音乐**。

### QQ 音乐 / 网易云音乐

依次尝试以下搜索词；前面的方案找到可用结果后不一定继续后续方案：

1. 原始歌名 + 歌手。
2. 去掉括号、方括号附注后的歌名 + 歌手（标题发生变化时）。
3. 必要时只搜索原始歌名或精简歌名，再检查候选歌手。

先拿到歌曲列表，在列表内评分、过滤版本，再根据歌曲 ID 获取歌词；不是直接搜索任意网页里的歌词文本。空歌词、不合格占位内容会被跳过，每个查询方案有候选尝试上限。同一录音的歌词不完整时，还可能比较另一份结果。

QQ 会尝试逐字歌词及译文，必要时退回普通歌词接口；网易云读取普通、翻译和逐字轨道。

### LRCLIB

先按歌名 + 歌手查询；未得到合格结果时，再尝试只用歌名查询。放宽查询后仍会检查歌手别名、标题、时长和版本，不是随便取一条同名歌曲。优先选择带时间轴的歌词，必要时使用纯文本。

## 4. 如何选结果

主要检查：

- 歌名匹配程度，包含标准化、相似度和部分跨文字转写处理。
- 歌手是否匹配。
- 播放器时长与候选时长的差距。
- Live、翻唱、伴奏等版本标签。
- 歌词是否真的有正文，而不是空内容、制作人员信息或平台占位提示。

通过门槛后，再综合匹配置信档位、译文覆盖率、逐字覆盖率、匹配分和正文完整度排序。分数是代码内部启发式分数，**不是准确率百分比**。

每个平台通常保留一份较优候选，再从平台候选中选主结果。并不是网易云永远优先，也不是最快返回的平台一定胜出。

专辑并非普通平台搜索的通用硬筛选条件；它主要参与下一步的身份补充匹配。

## 5. 为什么有时已经找到歌词，还会继续查询

如果没有找到歌词，或者来源不齐、逐字/翻译不完整，代码可能请求 iTunes 日本区目录，尝试把播放器提供的名字对应到另一种语言的歌名、歌手名。

这一步会结合标题、歌手、专辑、时长等信息。找到可信的不同名称后，再查询缺失或需要补充的歌词源。

这是音乐目录的别名匹配，不是用翻译模型凭空生成歌词。

## 6. 等待时间

一次平台并行查询的等待预算为 10 秒；首个完整平台候选返回后，还有最多约 9 秒的收集窗口，且不超过本轮预算。

**这不是整个流程绝对不超过 10 秒的保证**：iTunes 身份查询、后续平台查询，以及底层网络超时都可能增加总耗时。小窗可以接收第一轮的可用结果，主页目前等待最终结果。

因此反复手动“重试同一搜索”不一定能改善结果。本次界面不添加重试按钮，失败时只提示“找不到歌词”。匹配到错误版本仍有可能发生，界面不能自动知道用户认为哪句歌词不对。

## 7. 切源、换版本、导入分别是什么

- **切源**：在已经返回的平台候选之间切换，例如从 QQ 改成网易云，不等于重新搜索所有平台。本次小窗不再暴露这个操作入口。
- **换版本**：只向选定的平台重新查询，排除已经尝试过的歌曲 ID，再预览新的候选；可能是同名歌、另一录音或另一发行版本。
- **导入 LRC**：用户直接指定这首歌的本地歌词，优先级高于自动查询；删除后才恢复自动匹配。

版本管理和自定义歌词仍保留在应用内设置中，不放进小窗菜单。

## 8. 当前需要知道的限制

手动版本记忆主要由小窗在应用候选时读取。主页会把自动结果写入管理记录，但当前主页的本地取词路径并不直接读取手动固定候选。因此不能把主页与小窗的缓存、手选结果视为已经完全统一。

本次先改交互，不顺带重写这部分匹配策略。

## 源码入口

- `MainActivity.localPayload` / `fetchLyrics`：主页缓存与查询。
- `lyrics_overlay.html` 的 `resolveTrack` / `receiveLyrics`：小窗缓存与后台更新。
- `DirectLyricsRepository.resolveLyrics` / `resolveFromProviders`：并行查询与补充查询。
- `searchPlans` / `firstJsonMatch` / `qualityRank`：搜索词、候选筛选和排序。
- `resolveLocalizedIdentity`：跨语言身份补充。
- `LyricSourceManagerActivity.search` / `DirectLyricsRepository.rematch`：指定平台的下一候选。
